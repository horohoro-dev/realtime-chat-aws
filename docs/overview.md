# 概要

作成日：2026-11-25
更新日：2026-11-25

## 1. このリポジトリは何か

ルーム（チャットの部屋）の中で、メッセージと画像・動画・PDF を送り合えるチャットサービスを、AWS 上に作ったものです。設計の理由、IaC、CI/CD、監視、障害対応までを含めて示します。

このリポジトリの主題はインフラ、CI/CD、セキュリティ、運用です。フロントエンドとバックエンドは、インフラの上で動かすための最小限にしています。機能を足すのは、その機能でインフラの構成が変わるとき（リアルタイム通信、添付ファイルの処理など）に限ります。

## 2. 機能

- ルームの作成と一覧。ルームにメンバーを招待する
- ルームの中でのメッセージの送受信（WebSocket によるリアルタイム通信）
- 画像、動画、PDF の添付。画像と動画はサムネイルをチャット欄に表示する
- ログイン（Amazon Cognito）

## 3. 作らない機能

次の機能は、足してもインフラの構成がほとんど変わらないため、作りません。

- ドキュメントの共同編集。リアルタイムの同時編集は、アプリ側の作り込み（編集の衝突の解決など）が重い一方で、インフラはチャットの WebSocket の仕組みで足ります。
- メッセージの検索、既読、編集と削除、メンションなどの、チャットの細かな機能

次の機能は、ほかの作業を終えたあとに検討します。

- プロフィールのアイコン画像。添付ファイルの処理の仕組みを使えるため、インフラの追加はほぼありません。

## 4. データの扱い

- デモのデータは、すべて作者が作った架空のものです。
- 利用者の個人情報やファイルを預かるサービスとして、暗号化、アクセスの記録、ログの保存期間を設計の判断として文書に書きます。

## 5. 文書で示すこと

- 構成図と、サービスごとに選んだ理由（[ADR](adr/README.md)）
- Terraform によるモジュール化と、dev と prd の分離
- GitHub Actions による CI/CD。terraform plan の結果を PR に出し、脆弱性検査の結果を Artifact に残す
- マルチ AZ、バックアップ、WAF、最小権限の IAM
- 監視、アラート、Slack への通知
- SLO の目標値と根拠、わざと起こした障害の記録（ポストモーテム）と Runbook
- 月額の費用と、費用を抑えた工夫
- 今の構成の限界と、今後の課題
